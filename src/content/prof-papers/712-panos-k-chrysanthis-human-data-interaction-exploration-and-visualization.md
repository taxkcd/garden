## Paper overview

This paper discusses how advances in AI are transforming how people interact with and analyze data, especially large, complex, and unstructured data. It highlights challenges such as latency, scalability, trust, and usability in human-data interaction systems. The authors argue for integrated system designs that combine data management, AI, interfaces, and visualization to support real-time, trustworthy, and effective data exploration and analysis. They also emphasize the importance of human oversight and cross-disciplinary collaboration to address these challenges.

### Why it matters

**Research problem:** The paper addresses the challenge of designing interactive human-centered data systems that can handle large-scale, heterogeneous, and multimodal data in the AI era, while meeting strict latency, scalability, trust, and usability requirements. Existing systems are limited by traditional architectures and interaction paradigms that do not adequately support AI-driven analytics, multimodal data, or real-time human-AI collaboration.

**Why it matters:** As AI increasingly influences data analysis, users face difficulties exploring complex, unstructured data with traditional tools. Latency and scalability constraints disrupt analytical reasoning and reduce effectiveness. AI models introduce uncertainty and bias, requiring human oversight. Without new system designs, users cannot fully leverage AI capabilities or trust AI-generated insights, limiting the impact of data-driven decision making.

**Key contributions:**

- Identification of new requirements for human-data interaction systems in the AI era, including perceptually aligned latency, multimodal data handling, and trustworthy analysis.
- Emphasis on latency and scalability as fundamental barriers requiring new data management and system design techniques.
- Advocacy for end-to-end co-design of systems, interfaces, AI, and visualization to support adaptive, mixed-initiative exploration.
- Discussion of AI models' brittleness and the necessity of human-in-the-loop oversight.
- Presentation of visualization as an active, generative component guiding user attention and trust.

### Beginner — Latency-Aware Interactive Visualization Demo
*Effort: a weekend, ~8 hours*

You build a small web application that visualizes a moderately sized dataset with interactive filtering and updates, instrumented to measure and display latency aligned with human perceptual thresholds. The app demonstrates how interface responsiveness affects user experience by showing latency metrics and adapting visual updates to maintain perceptual latency under 100 milliseconds.

**Why it shows you understood the paper:** This project shows you grasp the paper's emphasis on latency as a fundamental barrier and the need for interface-aware system design to support effective human-data interaction.

**Grounded in:** Latency aligned with human cognition (order-of-millisecond) is critical for effective interactive analysis.

**Tech stack:** TypeScript, React, D3.js, Node.js, Express

**Data:** Use a public dataset such as the Iris dataset or a small CSV with categorical and numerical fields to simulate interactive filtering.

**Build it:**

1. Set up a React frontend with D3.js for rendering visualizations (e.g., scatterplot or bar chart).
2. Implement interactive filtering controls that update the visualization based on user input.
3. Measure the latency between user interaction and visualization update using performance APIs.
4. Display latency metrics on the interface and adapt update frequency or animation to keep latency perceptually low.
5. Test responsiveness with different dataset sizes and document latency observations.

**Ships as:** A GitHub repo with a React+D3 visualization app that reports and adapts to latency, with a README explaining the latency measurements and their relevance to human-data interaction.

**Stretch goal:** Add a simple caching or debounce mechanism to further reduce perceived latency during rapid interactions.

*Effort: 2 weekends, ~20 hours*

You implement a prototype system that supports multimodal querying (text + simple visual selection) over a public tabular dataset and integrates a small AI guidance component (e.g., GPT-3.5 or open LLM) to suggest next exploration steps or highlight interesting data points. You compare user experience metrics such as query latency and guidance usefulness against a baseline without AI guidance.

**Why it shows you understood the paper:** This project demonstrates your ability to co-design data querying, AI components, and interfaces as advocated by the paper, and to address challenges of multimodal data handling and AI-driven guidance.

**Grounded in:** Advocacy for end-to-end co-design of systems, interfaces, AI, and visualization to support adaptive, mixed-initiative exploration.

**Tech stack:** TypeScript, React, Node.js, Express, OpenAI API or Anthropic Claude API

**Data:** Use a public tabular dataset such as the UCI Adult Income dataset or a similar open dataset to simulate multimodal querying.

**Build it:**

1. Build a React frontend with controls for text queries and visual selection (e.g., brushing on a scatterplot).
2. Implement backend APIs to filter and return data based on combined multimodal queries.
3. Integrate an AI language model API to generate guidance messages or suggest next queries based on current user selections.
4. Measure query latency and collect simple user feedback on guidance usefulness via UI prompts.
5. Compare performance and user feedback metrics against a version without AI guidance.
6. Document the system design and evaluation results in the README.

**Ships as:** A GitHub repo with a full-stack multimodal querying app enhanced by AI guidance, including performance and user feedback comparisons documented in the README.

**Stretch goal:** Add provenance tracking of AI guidance suggestions and allow users to provide real-time feedback to improve trust.
