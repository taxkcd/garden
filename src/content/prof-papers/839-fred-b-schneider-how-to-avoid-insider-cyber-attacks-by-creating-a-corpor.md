- **Year:** 2021

## Paper overview

This paper discusses how insider cyber-attacks, where trusted insiders misuse their access, can bypass classical cybersecurity measures. It argues that building an organizational culture of trust combined with administrative procedures and people-based defenses is essential to effectively mitigate insider threats. The paper reviews best practices from both private sector and Department of Defense organizations, emphasizing the role of people, processes, and culture alongside technical controls.

### Why it matters

**Research problem:** Insider cyber-attacks are difficult to prevent because insiders have legitimate access and privileges that can be abused, circumventing traditional technical security measures.

**Why it matters:** Insider attacks threaten the confidentiality, integrity, and availability of critical organizational assets, can destabilize organizations, harm mission success, and damage customer trust. They also pose risks for supply chain attacks and accidental insider errors.

**Key contributions:**

- Identification of remarkably similar insider defense practices across diverse organizations despite different cultures and incentives.
- Highlighting the importance of people, processes, and culture in implementing insider defenses.
- Discussion of organizational structures such as two-person integrity, maker/checker, and independent collaborators to distribute trust.
- Recommendations for reducing super-user privileges via automation to limit insider risk.
- Insights on incentivizing trustworthy behavior and balancing security with employee morale.

### Beginner — Role-Based Access Control Simulator
*Effort: a weekend, ~8 hours*

You build a small web app that simulates an organization's role-based access control (RBAC) system with users, roles, and permissions. The app allows assigning roles to users and simulates access requests to resources, showing how trust is distributed and how two-person integrity or maker/checker patterns can be modeled.

**Why it shows you understood the paper:** This project demonstrates your grasp of the paper's key contribution on organizational structures that distribute trust and reduce insider risk by limiting super-user privileges and requiring multiple actors for sensitive actions.

**Grounded in:** Discussion of organizational structures such as two-person integrity, maker/checker, and independent collaborators to distribute trust.

**Tech stack:** TypeScript, React, Node.js, Express.js

**Data:** No external data needed; you simulate user-role-permission assignments and access requests within the app.

**Build it:**

1. Design a simple data model for users, roles, permissions, and resources.
2. Implement role assignment and permission checking logic in the backend.
3. Create a React frontend to manage users, assign roles, and simulate access requests.
4. Add UI to demonstrate two-person integrity by requiring two distinct users to approve sensitive actions.
5. Document how this simulates trust distribution and insider threat mitigation.

**Ships as:** A GitHub repository with a working RBAC simulator app and a README explaining how the app models insider defense organizational structures.

**Stretch goal:** Add logging and monitoring features to simulate human monitoring of access requests and flag unusual patterns.

**Grounded in:** Automated datacenter administration can replace many super-user roles, reducing insider risk.

**Tech stack:** Python 3.11, FastAPI, PostgreSQL, Docker

**Data:** No external dataset; you simulate privileged operations and user roles in a small-scale system.

**Build it:**

4. Build a simple dashboard to compare the number of manual versus automated privileged operations.
5. Analyze and document how automation reduces the need for super-user privileges and insider risk.

**Ships as:** A GitHub repo with the automated privilege reduction prototype, scripts, API, and a report comparing manual and automated privilege usage.

**Stretch goal:** Integrate role-based access control with the automation to enforce least privilege dynamically.
