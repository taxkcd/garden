## Paper overview

This paper investigates how large language models (LLMs) that translate natural language questions into SQL queries perform when the underlying database schema changes but the data and questions remain the same. The authors create multiple equivalent database schemas from a common entity-relationship (E/R) model and evaluate several leading LLMs on their consistency and correctness across these schema variants. They find that LLMs often produce inconsistent and incorrect SQL queries depending on the schema structure, highlighting a robustness problem in current text-to-SQL systems. Providing additional E/R context improves performance but does not fully solve the issue.

### Why it matters

**Research problem:** Do LLM-based text-to-SQL systems produce consistent and correct SQL queries when the database schema varies structurally but represents the same underlying data and semantics?

**Why it matters:** In real-world applications, the same data can be represented by multiple plausible relational schemas due to design choices like inheritance mapping, normalization, and relationship encoding. Users expect consistent query results regardless of schema variations. Current benchmarks do not evaluate this robustness, which is critical for reliable deployment of text-to-SQL systems by non-expert users.

**Key contributions:**

- A novel framework to generate and populate multiple equivalent relational schemas from a single E/R model by varying shredding strategies.
- A systematic evaluation methodology for testing LLM-based text-to-SQL robustness across schema variants with fixed data and questions.
- Empirical evidence showing substantial inconsistency and errors in SQL queries generated by leading LLMs across equivalent schemas.
- Demonstration that providing E/R diagram context improves but does not eliminate inconsistencies.
- Insight that current text-to-SQL benchmarks miss an important robustness dimension related to schema invariance.
