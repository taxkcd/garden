## Paper overview

This paper reviews the use of eye tracking technology integrated into virtual reality (VR) headsets. It covers the types of eye movements, methods to track them, and how eye tracking is applied in VR for display optimization, user interaction, collaboration, education, security, marketing, and clinical uses. The paper also discusses technical challenges such as data quality, latency, and calibration, and suggests areas for future research.

### Why it matters

**Research problem:** The paper addresses the need to understand and improve eye tracking applications in VR head-mounted displays (HMDs), including overcoming technical challenges like latency, precision, and calibration, to enhance VR experiences and enable new interaction modalities.

**Why it matters:** Eye tracking can significantly improve VR by enabling efficient rendering, natural user interaction, better collaboration, and clinical applications. However, current limitations in eye tracking technology hinder its full potential, affecting user comfort, immersion, and interaction accuracy.

**Key contributions:**

- Comprehensive overview of eye tracking applications in VR across multiple domains.
- Detailed explanation of eye movement types and tracking methods in VR HMDs.
- Identification of technical challenges such as data quality, latency, and calibration.
- Discussion of gaze-contingent display techniques to improve rendering efficiency and reduce VR sickness.
- Review of eye gaze-based user interaction techniques including selection, locomotion, and system control.

**Grounded in:** Detailed explanation of eye movement types and tracking methods in VR HMDs.

**Tech stack:** JavaScript, React, D3.js or Canvas API

**Data:** Synthetic gaze data generated to mimic fixations, saccades, and blinks as described in the paper.

**Build it:**

1. Create a React app with a canvas or SVG area for gaze visualization.
2. Implement functions to generate synthetic gaze points representing fixations, saccades, and blinks.
3. Build UI controls to switch between eye movement types and play/pause the gaze animation.
4. Visualize gaze points over time with distinct colors or shapes for each movement type.

### Intermediate — Simplified Foveated Rendering Prototype
*Effort: 1-3 weekends*

You implement a basic foveated rendering system in a simple 3D WebGL or Three.js scene that dynamically adjusts rendering resolution based on simulated gaze position. You compare rendering performance metrics with and without foveated rendering.

**Why it shows you understood the paper:** This project reproduces a core application and result from the paper — foveated rendering's performance benefits — demonstrating your ability to implement gaze-contingent display techniques and measure their impact.

**Grounded in:** Foveated rendering can save 50-70% of rendering performance costs by focusing high resolution on the fovea.

**Tech stack:** JavaScript, React, Three.js, WebGL

**Data:** Simulated gaze coordinates controlling the foveated rendering focus point; no real eye tracking data required.

**Build it:**

1. Set up a React app with a Three.js 3D scene containing multiple objects.
2. Implement a gaze simulation module that provides dynamic gaze coordinates over the scene.
3. Develop a foveated rendering shader or technique that renders high resolution near gaze and lower resolution in the periphery.
4. Measure and log frame rendering times and frame rates with and without foveated rendering enabled.
5. Create a UI to toggle foveated rendering and display performance metrics.
6. Write a README explaining foveated rendering, your implementation, and performance results.

**Ships as:** A GitHub repo with a React + Three.js app demonstrating foveated rendering and performance comparison, plus documentation linking the implementation to the paper's reported benefits.

**Stretch goal:** Integrate a simple calibration step to simulate gaze offset correction, addressing calibration challenges.
