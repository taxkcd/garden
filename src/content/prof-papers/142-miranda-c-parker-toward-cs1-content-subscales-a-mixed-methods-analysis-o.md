# 142 · Toward CS1 Content Subscales: A Mixed-Methods Analysis of an Introductory Computing Assessment

## Paper overview

This paper investigates whether the widely used Second CS1 (SCS1) assessment for introductory computer science can be divided into reliable subscales that measure specific computing concepts or question types. Using a combination of quantitative factor analyses and qualitative coding, the authors find that SCS1 items often cover multiple concepts and that subscales based on intended concepts or question types are unreliable. Instead, item features like readability and working memory demands better explain student performance. The paper concludes that SCS1 should be used as a whole and motivates future work to revise it to include valid subscales.

### Why it matters

**Research problem:** Determining whether the SCS1 assessment can be reliably decomposed into subscales that measure distinct CS1 concepts or question types, which would allow more fine-grained measurement of student knowledge.

**Why it matters:** Valid and reliable assessments with interpretable subscales are crucial for computer science education research to accurately measure student understanding, evaluate interventions, and guide curriculum design. Without verified subscales, conclusions drawn from partial use of SCS1 may be invalid.

**Key contributions:**

- Comprehensive mixed-methods analysis of the SCS1 assessment's internal structure and content.
- Evidence that SCS1 does not support reliable, interpretable subscales based on intended CS1 concepts or question types.
- Identification that many SCS1 items cover multiple concepts, complicating subscale construction.
- Discovery that data-driven factors align more with item features like readability and working memory demands than conceptual knowledge.
- Methodological roadmap for assessment developers to analyze and improve computing education instruments.

### Beginner — Reproduce SCS1 Overall Reliability Metric
*Effort: a weekend, ~6 hours*

You build a simple Python script that calculates the overall Cronbach's alpha reliability coefficient for a simulated dataset mimicking the SCS1 assessment's item responses. This reproduces the paper's reported overall reliability (α=0.78) to demonstrate understanding of classical test theory reliability metrics.

**Why it shows you understood the paper:** This project shows you understand the concept of reliability in assessments and how to compute it from item response data, directly reflecting the paper's finding that the SCS1 has acceptable overall reliability but poor subscale reliability.

**Grounded in:** Key result: Unidimensional CFA model showed acceptable overall reliability (α=0.78).

**Tech stack:** Python 3.11, numpy, pandas, scipy

**Data:** Simulated item response data based on the paper's description of SCS1 item characteristics, since no raw data or artifacts were released.

**Build it:**

1. Simulate a dataset of binary or polytomous item responses for 547 students and 27 items, reflecting typical SCS1 response patterns.
2. Implement a function to calculate Cronbach's alpha from the item response matrix.
3. Calculate and print the overall reliability coefficient.
4. Write a README explaining the calculation and how it relates to the paper's reported reliability.

**Ships as:** A GitHub repo with a Python script that computes and reports Cronbach's alpha for simulated SCS1 data, with documentation linking the metric to the paper's findings.

**Stretch goal:** Add item-level statistics such as item-total correlations and identify items with low discrimination, mirroring the paper's classical test theory analyses.
